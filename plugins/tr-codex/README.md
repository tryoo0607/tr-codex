# tr-codex

개인 kit — **22개 스킬**. `tr-kit-source`에서 `build.sh codex`로 생성(수동 유지 X).

## 스킬

| 스킬 | 발동 |
|---|---|
| `analysis` | 프로젝트/코드베이스 구조를 온보딩용 문서로 낼 때 발동 — "이 프로젝트 구조 분석해줘/온보딩 문서", "코드베이스 구조 한 장", "모듈 배선도·데이터흐름 그려서 정리". 멀티뷰·인라인 도식·각주 규격의 자체완결 HTML. 실코드 구현은 아님. |
| `api-handoff` | 백엔드 변경(API 스펙 변경·추가·삭제 등)을 **프론트에 넘길 요청서**로 산출할 때 발동 — "프론트 요청서 만들어줘/FE에 변경 알려줘/API 변경 핸드오프". 표 중심 정형 문서(변경표·FE영향·브레이킹·조치·롤아웃·예시). BE diff/PR에서 변경 자동 도출 가능, FE 소스 보이면 제안 patch도 산출. 실제 FE 구현·적용은 범위 밖. |
| `architecture` | 방법론·아키텍처 스타일·디자인 패턴을 **뭘 고려할지 메뉴로** 안내할 때 발동 — "어떤 방법론/패턴 고려하지?", "이 상황에 맞는 아키텍처 스타일", "이거 무슨 패턴이 맞아?". 2레벨 비처방 메뉴(①방법론·아키텍처 ②GoF+동시성 패턴+안티패턴). 강요하지 않는다 — 고르면 실행으로 넘긴다. 「계획」과 `review`가 소환한다. 도식=`diagram`. |
| `career` | 작업·성과를 커리어 자산으로 축적하거나 이력서·면접 재료로 추출할 때 발동 — "업무 로그 남겨줘", "성과 정리", "이번 달 뭐 했지". 로컬 git 이력에서 초안을 수확하고 raw 기록을 근거 있는 성과로 정제한다. |
| `ci` | CI/CD 파이프라인(**GitHub Actions**)을 작성·수정할 때 발동 — "CI 짜줘/워크플로 만들어줘/파이프라인 추가/actions 설정", "빌드·테스트 자동화 YAML". 스테이지(lint→test→build→deploy)·트리거·캐싱·secret 관례로 `.github/workflows/*.yml` 산출. 실패 디버그는 `odin:gh-fix-ci` 소프트의존. GitLab 등은 범위 밖(GHA 전용 — 회사는 project-local 우선). |
| `convention` | 이름·코딩 스타일·문서 작성 관례를 정하거나 조회·적용할 때 발동 — "이름 추천해줘/뭐라고 부르지", "이 코드 규칙 뭐야", "이 이름 괜찮아?", "docstring 어떻게 써", "README 형식". **"우리는 이렇게 쓴다"의 홈.** |
| `deps` | 의존성을 추가·업그레이드·제거하거나 취약점을 점검할 때 발동 — "이 라이브러리 추가/업글", "의존성 최신화", "취약점 있나". 리포트 먼저(영향도 포함) → 확인 → 실행. 자동 실행 X. |
| `diagram` | 다이어그램을 그리거나 유지할 때 발동 — "다이어그램/그려줘/class diagram/시퀀스/구성도/아키텍처 그림/토폴로지/ER/상태도". class·sequence·ER·state·flowchart·C4. 분석·설계·토폴로지에서 소환. Mermaid 텍스트 정본. |
| `dive` | 작업과 관련된 주제를 더 깊게 탐구하거나 복습할 때 발동 — "이거 파보자", "그게 뭔데?", "이 주제 좀 깊게", "요즘 뭐 배웠지". 작업을 막지 않는 비침습 학습 큐레이터이며, 자동 제안은 runtime profile에서 명시적으로 켠 경우에만 동작한다. |
| `git` | git 워크플로가 필요할 때 발동 — 커밋(단위·메시지)·브랜치 전략·머지/rebase·PR 작성. "커밋해줘/머지/브랜치 따줘/PR", 코드 변경을 git에 반영할 때. worktree 공간 생성은 project 소관, 여기선 그 안의 코드 흐름. |
| `kit` | 이 kit 자체를 설치·점검·업데이트하거나 스킬·컴포넌트를 저작할 때 발동 — "kit 설치/업데이트", "스킬 만들어줘/추가해줘", "스킬 출력 형식 설계", "kit 군살 점검". 공통 저작·검증과 호스트별 배포 채널을 연결한다. |
| `knowledge` | 조사·PoC·디버깅에서 얻은 재사용 가능한 지식을 Markdown repository에 축적·조회할 때 발동 — "이거 지식으로 남겨", "전에 알아낸 것 찾아줘", "내 지식 베이스에 저장". index와 상대 링크를 직접 순회하는 LLM-wiki 방식. |
| `logs` | 로그를 찾아 읽고 분석할 때 발동 — "로그 봐줘", "서버/앱 로그 확인", "이 에러 로그 분석", IntelliJ/컨테이너/서버 로그. **로그는 재료다** — 원인 규명은 「수행」의 디버깅이 한다. |
| `perf` | 성능을 점검·최적화할 때 발동 — "느려", "성능 체크해줘", "왜 느리지", "최적화". 측정 먼저(추측 최적화 금지) → 병목 특정 → 제안(리포트) → 확인 → 적용. |
| `profile-setup` | tr-kit의 non-secret 로컬 연결을 설정·점검할 때 발동 — "career/knowledge 저장소 연결", "handoff 경로 설정", "dive 자동 제안 켜기", "profile.d doctor". read-only plan을 먼저 보여주고 승인된 managed profile만 변경한다. |
| `project` | '`~/projects` 아래 프로젝트의 **공간과 기록 인프라**를 다룰 때 발동 — "프로젝트 새로 만들어줘", "worktree 따줘/정리해줘", "AGENTS.md 배치", "fork remote 구성", "백업 왜 안 돼/이 머신에 붙여줘", "이 문제 케이스로 남겨줘", "local-docs 마이그레이션". 코드 내용엔 손대지 않는다.' |
| `proofread` | 산문·README·설계 문서·자료조사 결과를 검수할 때 발동 — "검수해줘", "오타 봐줘", "이 글 봐줘". 오타·문법·일관성·출처/사실·톤을 확인한다. 코드는 code review 범위다. |
| `prototype` | 프론트 프로토타입·목업을 빠르게 만들 때 발동 — "프로토타입/목업 만들어줘", "이 화면 HTML로 그려줘/시안", "랜딩/대시보드 목업", "워치/모바일 화면 스케치". 단일 자체완결 HTML 목업. 목데이터·throwaway이며 실제 구현은 「수행」. |
| `review` | 작성된 코드를 검수할 때 발동 — "리뷰/검토해줘", diff·PR·브랜치·파일 리뷰. 이미 쓴 것을 severity 순으로 지적·제안한다(post-write). 손대기 전 **파악**은 알아내기 profile, 버그 **재현**은 「정의」 소관. |
| `secrets` | secret(자격증명·키·토큰)을 관리하거나 코드/커밋에 들어갔는지 검사할 때 발동 — "secret 어떻게 관리해", "이거 커밋해도 되나", "secret 검사해줘", "git-crypt 셋업", pre-commit 훅. **탐지와 처리는 한 몸이다.** |
| `session` | 세션·작업을 이관·위임하거나 원격 세션 무응답을 진단할 때 발동 — "세션 넘겨줘/롤오버/핸드오버", 컨텍스트 포화로 새 세션에 압축 이관, "이 작업 다른 세션/사람/에이전트에 넘겨줘", "세션이 멈췄어/반응 없어". state 기반 롤오버와 HandOff 규격으로 이어받을 경계를 남긴다. |
| `test` | 테스트를 작성·실행할 때 발동 — "테스트 써줘/돌려줘", "E2E 짜줘", "화면 흐름 테스트", 개발 후 자동검증, 케이스를 테스트로 승격. 유닛·통합(인프로세스)과 E2E(앱 구동) 둘 다. **갈림선 = 앱을 띄우나**. 리팩터 후 "뭐가 검증됐고 뭐가 남았나"를 추적할 때도(검증 커버리지). **"실데이터/운영 DB 떠서 돌려보자"** 도 여기 — 원본 보호 절차. |
